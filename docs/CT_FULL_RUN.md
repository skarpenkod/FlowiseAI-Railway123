# ТЗ: полная выгрузка CT-логов на VPS

**Цель:** прочитать все действующие CT-логи (~46 млрд записей) и получить `ct_domains.parquet` со всеми китайскими хостами (`.cn`, `.中国`, dnsmasq-china-list). Ожидается ~10–30 млн хостов.

**Код:** этот репозиторий, ветка `claude/confident-cerf-oquvho`, скрипт `ct_collect.py`. Он уже умеет всё нужное: оба типа логов, параллельность, паузы на 429, чекпоинты и агрегацию. Писать код не нужно, задача — запустить и довести до конца.

## 1. Сервер

| | Минимум | Зачем |
|---|---|---|
| CPU | 16 ядер | разбор ~10 тыс. записей/с на ядро |
| RAM | 16 ГБ | ~40 процессов плюс итоговая агрегация в DuckDB |
| Диск | 150 ГБ SSD | part-файлы (~30–50 ГБ) и временные файлы DuckDB |
| Канал | 1 Гбит/с, **безлимитный трафик** | придёт **~55 ТБ** |

**Важно про трафик:** облачные тарифы с лимитом (например, Hetzner Cloud — 20 ТБ) не подходят. Нужен выделенный сервер с безлимитом или тариф без платы за входящий трафик.

## 3. Замер скорости (5 минут)

```bash
python ct_collect.py --logs sycamore2027h1 --tail 2000000 --work work_test --out test.parquet
```

В логе будет строка `… entries/s`. На 1 ядро ожидается около 10 тыс./с. Пришлите это число и вывод `nproc`.

## 4. Полный прогон

Запускать в `tmux` или как systemd-сервис:

```bash
python ct_collect.py --logs all --exclude argon,xenon --since 13 \
    --procs 40 --workers 16 --work work --out ct_domains.parquet 2>&1 | tee -a ct.log
```

- `--exclude argon,xenon`: классические логи Google отдают ~1 тыс. записей/с на IP и будут читаться месяцы. Их сертификаты почти все есть в других логах.
- Ожидаемое время — **5–7 суток**, упирается в канал.
- **После падения, перезагрузки или Ctrl+C запускать ту же команду.** Каждый лог продолжит с последнего чекпоинта `work/ct/<лог>/state.json`, без потерь и дублей.
- Можно запускать порциями: `--hours 24` останавливает всё через сутки с сохранением чекпоинтов.

## 5. Контроль хода

```bash
grep "entries/s" ct.log | tail -30          # скорость и ETA по каждому логу
grep -E "ERROR|giving up" ct.log | tail     # проблемные логи
python - <<'EOF'
import json, glob
done = sum(json.load(open(f))["next"] - json.load(open(f))["start"] for f in glob.glob("work/ct/*/state.json"))
print(f"прочитано {done:,} записей")
EOF
```

Промежуточный результат в любой момент, не мешая основному процессу:

```bash
python ct_collect.py --aggregate-only --work work --out ct_partial.parquet
```

Если в логе `unreachable` — хост лога недоступен, это нормально для отключённых логов. Если `giving up` — лог упёрся в ошибки, перезапуск команды продолжит его.

## 6. Завершение

1. Когда все логи дошли до конца (ETA 0), запустить команду из п. 4 ещё раз: она дочитает записи, которые появились за время прогона.
2. Проверить результат:
   ```bash
   python validate.py ct_domains.parquet
   ```
   Должно быть `OK` и `control list: 20/20` (baidu.com, qq.com, sina.com.cn и т.д.).
3. Отдать `ct_domains.parquet`, `ct.log` и вывод `validate.py`.

## Приёмка

- Все логи из `log_list.json` (кроме Argon/Xenon) прочитаны до конца или помечены как недоступные, со списком.
- `validate.py` проходит, контрольный список найден полностью.
- В отчёте: сколько записей прочитано, сколько заняло времени, сколько хостов и доменов на выходе.
